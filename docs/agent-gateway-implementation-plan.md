# Agent Gateway 实施计划

依据 [多用户部署方案](agent-gateway-design.md)。首期目标是在一个 Kubernetes 集群内，让两个试点用户从同一域名登录现有 Kady Web App，分别在自己的常驻 Agent 上完成带文件的科研任务。下列目录和配置名称为建议，任务编号表示交付顺序，不代表工期。

## 待实施清单

每项括号内为前置任务。完成后在对应行勾选，并附 PR、测试结果或试点验收记录。首次可领取 A1；A1 完成后，服务骨架、数据模型、验签和部署模板可以分别推进。

### A · 服务基础

- [x] **A1 定义托管配置契约**（无）。记录域名、路径、OIDC 回调、受信签发方、服务身份、证书来源和配置责任人；用 A、B 两个用户示例走通请求路径。
- [x] **A2 建立独立服务**（A1）。在 `gateway/` 建立 Fastify 入口、启动命令、类型检查和配置校验；缺少必填配置时启动失败并指出缺项。
- [ ] **A3 打包与探针**（A2）。构建独立镜像，区分存活和就绪探针；验证 Gateway 可单独启动和重启，数据库不可用时不接收业务流量。

实施记录见 [Gateway 启动与配置契约](../gateway/README.md)。A2 已通过类型检查和探针测试。A3 已添加 Dockerfile，并用独立 Node 进程和临时 PostgreSQL 验证连接成功时就绪、数据库停止后返回 503 且进程存活。容器镜像构建和容器内启动仍待验证。

开发阶段使用 Gateway 内嵌的 PGlite，部署阶段使用外部 PostgreSQL。B1 的迁移和唯一约束需在两种后端上验证。

### B · 登录与注册表

- [ ] **B1 建立数据库迁移**（A1）。定义用户、OIDC 身份、登录会话、实例和归属表；验证空库迁移成功，重复身份或冲突归属被唯一约束拒绝。
- [ ] **B2 接入企业登录**（A2、B1）。实现登录发起和回调，校验授权流程并按 issuer、subject 识别用户；同一账号重复登录仍映射同一内部用户。
- [ ] **B3 实现登录会话**（B2）。设置主机限定的安全 Cookie，处理过期、注销及写请求的 CSRF 校验；验证已注销的 Cookie 和跨站写请求被拒绝。
- [ ] **B4 登记与解析实例**（A2、B1）。提供受限登记命令及按内部用户查找私有 Service 的接口；验证重复登记、归属冲突和未登记用户的处理。

### C · Gateway 与 Agent 互信

- [ ] **C1 实现 Agent 验签**（A1）。在托管模式下覆盖所有业务路由，校验签名、签发者、有效期、自身实例和所属用户；测试有效、过期及归属不符的请求。
- [ ] **C2 签发内部令牌**（A2、B3、B4）。只从已验证会话和受控注册表取用户及目标实例，经验证证书的 TLS 连接发送令牌；确认上游收不到浏览器登录 Cookie 或外部身份头。
- [ ] **C3 联调错路由与轮换**（C1、C2）。用两个测试 Agent 验证正确路由成功、A 误送到 B 时被拒绝；演练先发布新公钥、再切换签名密钥、最后移除旧公钥。

### D · 前端与代理

- [ ] **D1 接入共享 Web App**（A2、B3）。托管构建使用相对 API 地址，接入登录、注销和过期提示；确认浏览器请求始终发往同源入口。
- [ ] **D2 转发项目和文件请求**（C2）。保留项目选择、查询参数、状态码和文件流；通过模拟上游核对上传与下载内容一致，并验证用户生成 HTML 的预览和直接访问均受限。
- [ ] **D3 接通 Run 流式恢复**（D2）。关闭代理缓冲，配置空闲超时并禁止重试启动 Run 的 POST；模拟断线后用已有状态接口恢复，核对 Run ID、执行数和收到的帧。

### E · 私有实例和持久化

- [ ] **E1 编写部署模板**（A1）。为每位用户定义单写者工作负载、私有 Service、PVC、探针、资源限制及网络策略；渲染 A、B 两套配置，核对卷、用户身份和网络选择器互相独立。
- [ ] **E2 持久化用户状态**（A1）。配置项目根目录、Pi 用户目录和可写凭证目录；统一凭证加载与 Settings 的写入位置，用临时目录验证保存、更新、清除和重启读取。
- [ ] **E3 部署双用户试点环境**（A3、B4、C3、D1、D3、E1、E2）。准备证书、数据库、两个 IdP 测试账号和存储类，登记实例并配置真实入口；验证两用户均能登录，未就绪的实例返回明确错误。

### F · 验收与发布

- [ ] **F1 验收租户隔离**（E3）。以同名项目验证文件隔离、错误路由拒绝和集群网络策略生效；从公网入口复核生成内容的隔离。
- [ ] **F2 验收真实任务**（E3）。上传文件、启动 Run、断网重连并下载产物；记录同一 Run ID、单次执行和文件一致性，重启 Gateway 后复核登录状态。
- [ ] **F3 验收 Pod 重建**（E3）。替换 A 的 Pod，验证文件、旧对话、供应商授权、默认模型和技能；变更及清除测试密钥后再次重建，确认旧值不会恢复，B 的任务仍可访问。
- [ ] **F4 检查本地兼容与运维可见性**（E3）。运行受影响的检查和本地聊天冒烟测试；记录登录失败、路由失败及流中断的定位方法，用测试数据检查日志脱敏。
- [ ] **F5 演练回退并开放试点**（F1–F4）。登记镜像、迁移和备份版本，演练数据恢复及回退；确认回退后 Agent 仍为私有，再开放试点账号并保存验收记录。

## 首期任务与依赖

| 任务 | 依赖 | 实施内容 | 完成条件 |
|---|---|---|---|
| 1. 建立服务和部署契约 | 无 | 新增独立的 Fastify + TypeScript 服务（建议放在 `gateway/`），提供启动配置、健康检查、就绪检查和独立镜像。确定托管域名、OIDC 回调、集群内 TLS 信任链及运维负责人。保留本地双服务启动方式。 | 可单独启动和重启 Gateway。配置缺失时托管服务拒绝就绪。本地启动不依赖 Gateway 或数据库。 |
| 2. 接入登录和实例注册表 | 1 | 建立 PostgreSQL 迁移，记录内部用户、OIDC 身份、可撤销登录会话、Agent 归属及部署引用。对 `(issuer, subject)` 和首期一人一实例的归属关系设唯一约束。实现登录、回调、注销和受限的运维登记命令。 | 两个试点账号分别绑定私有 Service。重复登记不会产生第二条归属，未登记账号得到明确提示。注销后旧 Cookie 无法再发起 API 请求。 |
| 3. 建立 Gateway 到 Agent 的身份校验 | 1；联调需 2 | Gateway 根据当前会话选取 Agent，剥离客户端身份头与网关 Cookie，经 TLS 发出短期签名令牌。托管 Agent 在业务路由前核验签名、签发者、有效期及部署时配置的用户 ID、Agent ID。私钥只交给 Gateway，制定公钥轮换步骤。 | 正确归属可访问；过期令牌、错误用户、错误实例均被拒绝。注册表误将 A 指向 B 时，B 拒绝请求。 |
| 4. 接通现有 Web App 与流式代理 | 2、3 | 托管版构建 `web/` 时设置 `NEXT_PUBLIC_ADK_API_URL=/api/kady`。入口将页面交给 Next.js，将认证和 API 路径直接交给 Gateway。实现登录过期提示、Cookie 和 CSRF 防护，保留项目选择、查询参数、流式响应及文件请求语义。 | 浏览器能登录、选择项目、上传下载文件并逐帧收到 SSE。断线后通过已有 Run 状态接口接回原 Run；代理不会重发启动 Run 的 POST。 |
| 5. 部署两套私有 Agent 并持久化 | 1；身份验证需 3 | 在建议的 `deploy/kubernetes/` 提供可重复使用的模板，手工部署两套 Agent、私有 Service 和独立 PVC。配置默认拒绝的网络策略、必要出站、资源限制和探针。升级采用单写者策略。 | 两套实例不能互访或挂载对方数据；Gateway 可通过受信 TLS 连接各自的 Service DNS。重建任一 Pod 后，通过下述持久化验收。 |
| 6. 端到端验收与试点发布 | 4、5 | 经实际 TLS 入口运行下列验收用例，记录结果和版本。先开放试点账号，监测登录失败、路由失败、SSE 中断及就绪状态。日志排除凭证、文件内容和对话正文。 | 全部验收项通过，完成一次升级和回退演练，再扩大用户范围。 |

**并行安排。** 服务配置契约确定后，可同时开发登录与注册表、Agent 验签和 Kubernetes 模板。流式代理先用模拟上游验证，最终以真实入口和两个用户实例联调为准。

## 仓库改动落点

- **前端和入口。** 检查 [前端 API 地址配置](../web/src/lib/projects.ts) 和 [现有单端口代理](../web/server.mjs)。托管版沿用现有公开路径，通过 Gateway 动态路由。核对 Cookie 转发，仅保留 Agent 确实需要的应用状态。对生成的 HTML 同时检查预览和直接打开文件两条路径，首期使用下载或禁用脚本的沙箱预览。
- **Agent 身份和 Run。** 在 [服务入口](../server/src/index.ts) 注册托管模式鉴权，明确探针路径和业务路径。复用 [Session 路由](../server/src/api/sessions.ts) 的启动、状态和恢复协议。网络断开只表示输出连接中断；Pod 被替换时，内存中的执行可能中断，界面应显示真实状态。
- **用户状态。** 将每个用户的项目根目录、有效 Pi 用户目录、可写的凭证配置目录分别映射至其专属卷。为 [启动环境加载](../server/src/env.ts) 和 [Settings 凭证写入](../server/src/api/credentials.ts) 使用同一托管配置路径。挂载凭证文件的父目录，以支持安全替换文件。维护原有环境变量优先级和清除行为。
- **交付物。** Gateway 代码与镜像、数据库迁移、运维登记命令、部署模板、示例配置，以及涵盖首次部署、凭证轮换、故障定位和回退的操作说明。示例中只放占位值。

## 首期验收记录

| 场景 | 操作与通过标准 |
|---|---|
| 身份与隔离 | A、B 使用同名项目，各自只能看到自己的文件。用受控测试映射制造误路由时请求被拒绝。校验无会话、会话过期、注销和跨站写请求的处理。 |
| 真实任务 | 从公网入口上传文件，启动一次 Run，观察输出在结束前到达。中断浏览器连接后重新接入，核对 Run ID 和执行记录，并检查下载文件内容一致。 |
| 用户环境恢复 | 配置测试供应商凭证、默认模型和用户级技能，创建对话并写入文件。替换 Pod，验证旧对话可继续、默认设置及技能可用。更新或清除凭证后再次重建，确认旧值不再生效。 |
| 服务故障 | 重启 Gateway，验证有效登录会话可继续使用。将某个 Agent 置为未就绪，确认其用户看到可理解的错误，另一用户可以继续工作。 |
| 生成内容 | 用包含无害脚本标记的测试 HTML 覆盖预览与原始文件入口，验证脚本不能以主站身份运行。确认网关日志没有记录测试密钥、Cookie、文件正文或聊天内容。 |
| 本地兼容 | 运行受影响的前后端测试和类型检查，再以本地模式打开项目并发起聊天，确认现有单用户部署可继续使用。 |

## 上线与回退

发布前准备测试 IdP 客户端、两个账号、数据库、可用的存储类、执行 NetworkPolicy 的集群网络和 TLS 证书。先部署兼容的数据库迁移与私有 Agent，再部署 Gateway、共享前端和入口路由，最后开放试点。登记镜像版本、数据库版本及 PVC 备份并验证可恢复。遇到隔离、凭证恢复或重复执行问题时暂停新请求，保留数据库和用户卷，恢复上一组兼容版本；首次发布没有可回退版本时关闭试点入口。回退期间继续保持 Agent 私有。
