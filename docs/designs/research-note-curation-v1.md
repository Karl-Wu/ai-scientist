# 笔记候选生成与确认

笔记面板打开后显示已保存笔记，使用现有「新建笔记页」入口。任务菜单的「从此任务创建笔记」、回答底部的「从此回答创建笔记」，以及文件、结果和 PDF 批注入口都进入同一个笔记编辑器，并带入对应出处。

用户可以直接手写，也可以选项目专家生成候选。项目设置中的默认专家会预选，生成由用户触发。专家可以在一次生成中返回多种已有笔记类型。

## 候选如何展示和确认

| 结果 | 界面 |
| --- | --- |
| 没有候选 | 说明本次没有候选，返回编辑后可修改材料或切换专家。 |
| 一页 | 默认展开、勾选。用户检查或修改后点击保存。 |
| 多页 | 每张卡片显示类型、标题和综述预览。展开可编辑标题、综述和对应字段。默认全不勾选，支持逐页勾选或全选。 |
| 保存完成 | 每张卡片显示保存结果。成功页退出选择范围，失败页保留编辑内容并可单独重试。若响应丢失，重试沿用原请求和原内容。 |

同一次生成的候选共用编辑器当前选定的出处。候选审阅区显示所用专家、出处及已有的材料摘录提示。用户返回编辑时，原手写内容仍可用。

## API

- `POST /notes/draft` 加 `format: "candidates"` 后返回 `candidates`、`draftCredit` 和现有的摘录与检查信息。每个候选包含 `requestId`、`type`、`title`、`summary`、`fields`。结果可以为空，上限为八页。调用只生成候选，保存由后续确认触发。
- `POST /notes/batch` 接收勾选后的 `pages`、共用的 `draftCredit`，以及可选的 `task` 或 `source`。返回 `results`，按 `requestId` 对应每页，结果包含已保存的笔记页或失败码。单页失败时，同一批里的其他页仍继续保存。
- 每页的 `requestId` 在生成时分配。同一请求和内容重试返回原笔记页。同一 ID 提交不同内容会返回该页的冲突结果。
- `POST /notes` 继续处理手工新增的单页笔记，省略 `format` 的旧起草调用继续返回单页建议。
